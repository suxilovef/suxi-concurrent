## 1. CopyOnWriteArrayList（COW）

### 1.1 设计思想：写时复制

```
核心：读不加锁，写时"复制一份新数组"，修改后替换引用

┌─────────────────────────────────────────────┐
│ 写操作 add(value)：                           │
│  1. 获取 ReentrantLock（写锁）                 │
│  2. 复制旧数组 → 新数组（长度 +1）              │
│  3. 新数组最后一位放新元素                      │
│  4. volatile array 引用指向新数组              │
│  5. 释放锁                                    │
│                                              │
│ 读操作 get(i)：                               │
│  直接读 volatile array（无锁！）                │
└─────────────────────────────────────────────┘
```

```java
// CopyOnWriteArrayList 核心字段
public class CopyOnWriteArrayList<E> {
    // volatile 数组引用：写时替换，读时直接拿
    private transient volatile Object[] array;

    // 写锁
    final transient ReentrantLock lock = new ReentrantLock();
}
```

### 1.2 add() 源码

```java
public boolean add(E e) {
    final ReentrantLock lock = this.lock;
    lock.lock();                       // ① 写锁（读不需要）
    try {
        Object[] elements = getArray();
        int len = elements.length;
        Object[] newElements = Arrays.copyOf(elements, len + 1);  // ② 复制
        newElements[len] = e;          // ③ 尾部加新元素
        setArray(newElements);         // ④ 替换引用（volatile 写）
        return true;
    } finally {
        lock.unlock();
    }
}
```

### 1.3 get() 源码 —— 无锁

```java
public E get(int index) {
    return get(getArray(), index);   // 直接读 volatile array
}

// 读线程永远读到"某一时刻的完整快照"
// 不阻塞、不抛 ConcurrentModificationException
```

### 1.4 关键特性

| 特性 | 说明 |
|---|---|
| 读无锁 | 读操作没有任何锁，性能极高 |
| 写互斥 | 写操作加 ReentrantLock（写写互斥） |
| 弱一致性 | 读线程可能读到旧数据（读的是旧数组快照） |
| 迭代器安全 | 迭代器遍历的是快照，不抛 CME |
| 内存开销 | 每次写都复制整个数组（O(n)） |

### 1.5 适用场景 & 局限性

```
✅ 适用：读多写极少
   监听器列表、配置白名单、黑名单、缓存刷新

❌ 不适用：
   写频繁（每次写 O(n) 复制）
   数据量大（百万级数组复制 = 灾难）
   强一致性需求（读可能旧）
```

### 1.6 对比总结

| | CopyOnWriteArrayList | 普通 ArrayList | Collections.synchronizedList |
|---|---|---|---|
| 读并发 | ✅ 无锁 | ❌ 不安全 | ❌ 全锁 |
| 写并发 | ✅ 锁 + 复制 | ❌ 不安全 | ✅ 锁 |
| 读性能 | 极高 | 高 | 低（锁开销） |
| 写性能 | 低（复制） | 高 | 低（锁开销） |
| 一致性 | 弱 | — | 强 |
| 适用 | 读多写少 | 单线程 | 一般并发 |

## 2. BlockingQueue 体系

### 2.1 接口的 4 组方法（🛠️ 必背）

BlockingQueue 的方法分为 4 组，行为完全不同：

| 行为 | 抛异常 | 返回特殊值 | 阻塞 | 超时 |
|---|---|---|---|---|
| 插入 | `add(e)` | `offer(e)` | `put(e)` | `offer(e, t, unit)` |
| 移除 | `remove()` | `poll()` | `take()` | `poll(t, unit)` |
| 检查 | `element()` | `peek()` | — | — |
| 失败行为 | 抛异常 | 返回 false/null | 阻塞等待 | 超时后返回特殊值 |

```
示例：
  queue.add(e)        → 队列满 → IllegalStateException
  queue.offer(e)      → 队列满 → false
  queue.put(e)        → 队列满 → 阻塞等待
  queue.offer(e, 1s)  → 队列满 → 最多等 1 秒 → 还满 → false
```

### 2.2 5 种 BlockingQueue 总览（🛠️ 选型表）

| 实现 | 底层 | 容量 | 锁 | 特点 | 适用 |
|---|---|---|---|---|---|
| **ArrayBlockingQueue** | 数组 | 有界 | 单锁双条件 | 固定容量、可公平 | 固定大小任务队列 |
| **LinkedBlockingQueue** | 链表 | 有界/无界 | **双锁** | 吞吐量高 | 线程池默认队列 |
| **SynchronousQueue** | 无存储 | 0 | CAS | 直接交付 | CachedThreadPool |
| **PriorityBlockingQueue** | 二叉堆 | 无界 | 单锁 | 优先级排序 | 优先级任务 |
| **DelayQueue** | 二叉堆 | 无界 | 单锁 | 延迟到期 | 定时任务 |

## 3. ArrayBlockingQueue 详解

### 3.1 结构

```java
public class ArrayBlockingQueue<E> {
    final Object[] items;          // 环形数组
    int takeIndex;                 // 取指针
    int putIndex;                  // 放指针
    int count;                     // 元素个数

    final ReentrantLock lock;      // ★ 单锁（读写共用一把锁）
    private final Condition notEmpty;   // 取：队列空等待
    private final Condition notFull;    // 放：队列满等待
}
```

### 3.2 为什么单锁？

```
单锁的缺点：put 和 take 互斥（生产时不能消费）
单锁的好处：简单、内存一致性强
LinkedBlockingQueue 双锁：put/take 各自独立锁 → 吞吐更高

→ ArrayBlockingQueue 用"单锁双条件"：
  锁只有一个，但 Condition 有两个（精确唤醒）
  公平模式：new ArrayBlockingQueue<>(10, true)
```

### 3.3 环形数组

```
ArrayBlockingQueue 是"环形数组"：
  放：items[putIndex++]（到尾部回到 0）
  取：items[takeIndex++]（到尾部回到 0）

  putIndex = (putIndex + 1) % items.length
  takeIndex = (takeIndex + 1) % items.length
```

## 4. LinkedBlockingQueue 详解

### 4.1 结构 —— 双锁

```java
public class LinkedBlockingQueue<E> {
    // 链表节点
    static class Node<E> { E item; Node<E> next; }

    // ★ 两把锁：
    final ReentrantLock takeLock = new ReentrantLock();   // 取锁
    final ReentrantLock putLock = new ReentrantLock();    // 放锁

    // 两个条件：
    final Condition notEmpty = takeLock.newCondition();   // 取等待
    final Condition notFull = putLock.newCondition();     // 放等待
}
```

### 4.2 为什么双锁？

```
双锁的意义：put 和 take 可以同时进行！

  消费者 take 时只需要 takeLock
  生产者 put 时只需要 putLock
  → 生产和消费真正并行 → 吞吐量高于单锁

代价：
  实现复杂（count 用 AtomicInteger 保证两个锁的共享计数安全）
  内存一致性弱于单锁
```

### 4.3 Array vs Linked 选型

| 维度 | ArrayBlockingQueue | LinkedBlockingQueue |
|---|---|---|
| 底层 | 数组（固定容量） | 链表（动态节点） |
| 锁 | 单锁 | 双锁 |
| 吞吐 | 中 | 高（读写并行） |
| 内存 | 预分配固定 | 按需分配 |
| 无界 | 不支持 | 支持（默认 Integer.MAX） |
| GC | 元素复用（不删除） | 节点创建/销毁频繁 |
| 适用 | 容量固定、实现简单 | 吞吐优先、可能无界 |

## 5. SynchronousQueue（零容量）

### 5.1 核心概念

```
SynchronousQueue 没有内部容量！
put() 必须等一个 take() 来"接走"数据，否则阻塞
take() 必须等一个 put() 来"交付"数据，否则阻塞

不是队列，是"握手通道"（Handoff）

put(1) ──────→ [直接交付] ←────── take()
生产者            →            消费者
      没有中间存储！数据直接交给消费者
```

### 5.2 两种实现

```
公平模式（TransferQueue）：FIFO 队列，先到先配对
非公平模式（TransferStack）：LIFO 栈，后到先配对（默认）

new SynchronousQueue()         → 非公平（TransferStack）
new SynchronousQueue(true)     → 公平（TransferQueue）
```

### 5.3 为什么 CachedThreadPool 用它？

```java
// newCachedThreadPool 的实现：
new ThreadPoolExecutor(0, Integer.MAX_VALUE,
    60L, TimeUnit.SECONDS,
    new SynchronousQueue<Runnable>());   // ← 零容量队列

// 意义：
// 每个提交的任务 → put → 必须立刻被 take 接走
// → 没有排队 → 线程按需创建（maxPoolSize=MAX_VALUE 几乎不设上限）
// → 核心线程数为 0：空闲线程 60s 后被回收
// → 注意：任务提交速度极快时线程数会暴涨（这是它的风险）
```

## 6. PriorityBlockingQueue & DelayQueue

### 6.1 PriorityBlockingQueue（无界优先队列）

```
底层：二叉堆（数组实现）
排序：自然序 / Comparator
特性：无界（可能 OOM）！出队的是"最小/优先级最高"的元素

使用：
  PriorityBlockingQueue<Task> queue = new PriorityBlockingQueue<>();
  queue.add(task1);   // 按优先级自动调整位置
  Task t = queue.take();   // 取优先级最高的
```

### 6.2 DelayQueue（延迟队列）

```
底层：PriorityBlockingQueue（按延迟时间排序）
元素要求：实现 Delayed 接口（getDelay + compareTo）
特性：take() 时，如果队首未到期 → 阻塞等待到到期时间

经典应用：
  - 订单超时取消（下单后 30 分钟未支付 → 取消）
  - 定时任务调度（ScheduledThreadPoolExecutor 内部就是 DelayQueue）
  - 缓存过期清理
```

```java
// Delayed 接口：元素必须实现
public interface Delayed extends Comparable<Delayed> {
    long getDelay(TimeUnit unit);  // 剩余延迟时间
}

// 使用
DelayQueue<OrderTimeoutTask> queue = new DelayQueue<>();
queue.add(new OrderTimeoutTask(orderId, 30 * 60 * 1000));  // 30 分钟后到期

// 另一个线程
OrderTimeoutTask task = queue.take();  // 阻塞到最早的任务到期
cancelOrder(task.getOrderId());        // 到期 → 处理
```

### 6.3 Leader-Follower 模式（◈◈ 了解）

```
DelayQueue 的 take() 内部实现了一个 Leader-Follower 模式：

  Leader：最早到期的等待者（负责计时唤醒）
  Follower：其他等待者（不自己计时，等待 Leader 的信号）

好处：同一时刻只有一个线程在"计时等待"（避免多个线程都定闹钟）
```

## 7. 其他并发容器（○ 了解）

### 7.1 ConcurrentLinkedQueue

```
无界无锁队列（Michael-Scott 算法，CAS 实现）
线程安全 + 无锁 → 高吞吐
但没有"阻塞"能力（offer/poll 立即返回）
适用：不要求阻塞的并发队列（Netty 的 Channel 队列）

⚠️ 注意：size() 是 O(n) 且不精确 → 不要用 size() 判断空
   用 isEmpty()
```

### 7.2 ConcurrentSkipListMap / Set

```
底层：跳表（SkipList）
特性：线程安全 + 有序（对比 CHM 无序）
复杂度：O(log n)
适用：需要有序并发 Map（如排行榜、区间查询）
```

### 7.3 容器选型决策树（🛠️ 日常必用）

```
需要 Map？
  ├─ 需要有序 → ConcurrentSkipListMap
  └─ 无序 → ConcurrentHashMap
需要 List？
  ├─ 读多写少 → CopyOnWriteArrayList
  └─ 一般并发 → Collections.synchronizedList
需要 Queue？
  ├─ 需要阻塞 → 5 种 BlockingQueue（按需选）
  ├─ 无锁不阻塞 → ConcurrentLinkedQueue
  └─ 单线程 → ArrayDeque/LinkedList
需要 Set？
  ├─ 需要有序 → ConcurrentSkipListSet
  └─ 无序 → ConcurrentHashMap.newKeySet()
```

## 8. 生产注意事项 & 常见坑点

### 🕳️ 坑 1：SynchronousQueue 的 put 会阻塞

```java
// ❌ 没有消费者 → 无限阻塞
queue.put(item);   // 永久等待 take

// ✅ 用 offer 带超时
boolean ok = queue.offer(item, 1, TimeUnit.SECONDS);
if (!ok) {
    // 降级处理
}
```

### 🕳️ 坑 2：无界队列 OOM

```java
// ❌ LinkedBlockingQueue 默认无界（Integer.MAX_VALUE）→ 任务堆积 → OOM
new LinkedBlockingQueue<>();   // 无界！

// ✅ 一定要指定容量
new LinkedBlockingQueue<>(1000);   // 有界

// 线程池场景：无界队列 = 线程数永远不增长 + OOM 风险
```

### 🕳️ 坑 3：DelayQueue 的元素必须实现 Delayed 接口

```java
// ❌ 直接放普通对象 → ClassCastException
delayQueue.add("hello");  // String 不是 Delayed

// ✅ 必须包装成 Delayed
delayQueue.add(new MyDelayedTask(taskId));
```

### 🕳️ 坑 4：CopyOnWriteArrayList 写频繁时性能灾难

```java
// ❌ 高频写入场景用 COW → 每次写复制整个数组
for (int i = 0; i < 100000; i++) {
    list.add(i);   // 每次 O(n) 复制 → O(n²) 总开销
}

// ✅ 高频写场景换别的
```

### 🕳️ 坑 5：ConcurrentLinkedQueue.size() 不精确

```java
// ❌ size() 是 O(n) 且并发下不精确
if (queue.size() > 100) { ... }   // 可能不准

// ✅ 用 isEmpty() 判断空（O(1)）
if (queue.isEmpty()) { ... }
```

## 9. 面试高频考点

1. **CopyOnWriteArrayList 的原理？什么时候用？**
   → 写时复制（写复制数组+替换引用，读无锁）。读多写少场景。写频繁 O(n) 复制。

2. **ArrayBlockingQueue 和 LinkedBlockingQueue 的区别？**
   → 数组 vs 链表、单锁 vs 双锁、固定容量 vs 可无界。Linked 吞吐更高。

3. **SynchronousQueue 是什么？为什么 CachedThreadPool 用它？**
   → 零容量"握手通道"。任务必须被新线程立刻接走 → 线程按需创建、不堆积。

4. **DelayQueue 怎么实现延迟？**
   → PriorityBlockingQueue 按到期时间排序 + Leader-Follower 模式计时等待。

5. **BlockingQueue 的 4 组方法各在什么场景用？**
   → put/take（阻塞，生产者消费者主线程）；offer/poll（非阻塞，试探）；add/remove（抛异常，不推荐）；offer(e,t)/poll(t)（超时，限时操作）。

## 10. 实战练习

### 练习 1：用 BlockingQueue 实现生产者-消费者（45 分钟）

```java
package com.sw.yang.concurrent.juc.container;

import org.junit.jupiter.api.Test;
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * 练习 1：用 ArrayBlockingQueue 实现生产者-消费者（生产推荐写法）
 *
 * 对比 02-03 的 wait/notify 手写版本 → 代码量减少 80%
 */
public class BlockingQueueProducerConsumerTest {

    private final BlockingQueue<Integer> queue = new ArrayBlockingQueue<>(10);
    private final AtomicInteger produced = new AtomicInteger(0);
    private final AtomicInteger consumed = new AtomicInteger(0);
    private volatile boolean running = true;

    @Test
    public void testProducerConsumer() throws InterruptedException {
        Thread[] producers = new Thread[2];
        Thread[] consumers = new Thread[3];

        for (int i = 0; i < 2; i++) {
            producers[i] = new Thread(() -> {
                while (running) {
                    try {
                        queue.put(produced.incrementAndGet());  // 满则阻塞
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        return;
                    }
                }
            }, "producer-" + i);
            producers[i].start();
        }

        for (int i = 0; i < 3; i++) {
            consumers[i] = new Thread(() -> {
                while (running) {
                    try {
                        queue.take();   // 空则阻塞
                        consumed.incrementAndGet();
                    } catch (InterruptedException e) {
                        Thread.currentThread().interrupt();
                        return;
                    }
                }
            }, "consumer-" + i);
            consumers[i].start();
        }

        Thread.sleep(2000);
        running = false;
        // 中断阻塞在 put/take 上的线程（interrupt 能打断阻塞）
        for (Thread t : producers) t.interrupt();
        for (Thread t : consumers) t.interrupt();
        for (Thread t : producers) t.join();
        for (Thread t : consumers) t.join();

        System.out.println("生产: " + produced.get() + ", 消费: " + consumed.get());
        System.out.println("队列残留: " + queue.size());
        System.out.println("✅ BlockingQueue 生产者-消费者运行完成（代码量是 wait/notify 的 1/5）");
    }
}
```

### 练习 2：DelayQueue 订单超时取消（60 分钟）★必做

```java
package com.sw.yang.concurrent.juc.container;

import org.junit.jupiter.api.Test;

import java.util.concurrent.DelayQueue;
import java.util.concurrent.Delayed;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * 练习 2：DelayQueue 实现订单超时自动取消（真实业务场景）
 *
 * 模拟：三个订单分别 1 秒 / 2 秒 / 5 秒后过期，按到期时间自动取消
 */
public class OrderTimeoutTest {

    static class Order implements Delayed {
        final String orderId;
        final long expireTime;  // 到期时间（毫秒）

        Order(String orderId, long delayMs) {
            this.orderId = orderId;
            this.expireTime = System.currentTimeMillis() + delayMs;
        }

        @Override
        public long getDelay(TimeUnit unit) {
            return unit.convert(expireTime - System.currentTimeMillis(), TimeUnit.MILLISECONDS);
        }

        @Override
        public int compareTo(Delayed other) {
            return Long.compare(this.expireTime, ((Order) other).expireTime);
        }
    }

    private final DelayQueue<Order> timeoutQueue = new DelayQueue<>();
    private final AtomicInteger cancelled = new AtomicInteger(0);

    @Test
    public void testOrderTimeout() throws InterruptedException {
        // 订单超时检查线程（常驻）
        Thread checker = new Thread(() -> {
            while (true) {
                try {
                    Order order = timeoutQueue.take();  // 阻塞到最早订单到期
                    System.out.println("⏰ 订单 " + order.orderId + " 超时未支付 → 自动取消");
                    cancelled.incrementAndGet();
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                    return;
                }
            }
        }, "order-timeout-checker");
        checker.setDaemon(true);
        checker.start();

        // 模拟下 3 个订单，不同超时时间
        System.out.println("下单 3 个订单...");
        timeoutQueue.add(new Order("O-001", 2000));  // 2 秒后过期
        timeoutQueue.add(new Order("O-002", 5000));  // 5 秒后过期
        timeoutQueue.add(new Order("O-003", 1000));  // 1 秒后过期

        // 等待所有订单到期
        Thread.sleep(6500);
        System.out.println("已取消订单数: " + cancelled.get());
        System.out.println(cancelled.get() == 3
                ? "✅ 3 个订单全部按时取消（DelayQueue 生效）"
                : "❌ 取消数量不对");

        // 验证顺序：O-003 最先到期，O-002 最后
        System.out.println("✅ 取消顺序验证：观察输出时间（O-003 → O-001 → O-002）");
    }
}
```

### 练习 3：CopyOnWriteArrayList 监听器（30 分钟）

```java
package com.sw.yang.concurrent.juc.container;

import org.junit.jupiter.api.Test;

import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * 练习 3：CopyOnWriteArrayList 实现线程安全的监听器列表
 *
 * 场景：事件总线，多个线程注册/移除监听器，事件发布时遍历所有监听器
 */
public class ListenerTest {

    interface Listener {
        void onEvent(String event);
    }

    static class EventBus {
        // 监听器列表：读多写少（注册/移除少，事件分发多）
        private final List<Listener> listeners = new CopyOnWriteArrayList<>();
        private final AtomicInteger delivered = new AtomicInteger(0);

        public void register(Listener listener) { listeners.add(listener); }
        public void unregister(Listener listener) { listeners.remove(listener); }

        public void publish(String event) {
            for (Listener l : listeners) {   // 遍历时安全（快照迭代器）
                l.onEvent(event);
                delivered.incrementAndGet();
            }
        }
    }

    @Test
    public void testEventBus() throws InterruptedException {
        EventBus bus = new EventBus();

        // 注册 5 个监听器
        for (int i = 0; i < 5; i++) {
            final int id = i;
            bus.register(event -> System.out.println("Listener-" + id + " 收到: " + event));
        }

        // 一个线程反复发布事件，另一个线程同时注册/移除监听器
        Thread publisher = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                bus.publish("event-" + i);
            }
        }, "publisher");

        Thread modifier = new Thread(() -> {
            for (int i = 0; i < 100; i++) {
                bus.register(event -> { /* 动态注册 */ });
                if (i % 2 == 0) {
                    bus.unregister(bus.listeners.get(0));  // 动态移除
                }
            }
        }, "modifier");

        publisher.start();
        modifier.start();
        publisher.join();
        modifier.join();

        System.out.println("✅ 发布/注册/移除并发执行无异常（CopyOnWriteArrayList 快照迭代器）");
    }
}
```

## 11. 自测题

1. **CopyOnWriteArrayList 的迭代器为什么不抛 ConcurrentModificationException？**
   <details><summary>答案</summary>

   迭代器遍历的是"获取时的数组快照"（volatile array 引用），后续 add/remove 会创建新数组替换引用，但迭代器仍持有旧数组引用 → 不冲突 → 不抛 CME。
   </details>

2. **ArrayBlockingQueue 和 LinkedBlockingQueue 各适合什么场景？**
   <details><summary>答案</summary>

   Array：容量固定、实现简单、单锁（生产消费互斥）；Linked：双锁吞吐高、可无界（有 OOM 风险）。线程池任务队列一般用 Linked（高吞吐）。
   </details>

3. **SynchronousQueue 为什么"没有容量"？**
   <details><summary>答案</summary>

   设计目标就是"直接交付"（Handoff）：put 必须等 take，take 必须等 put，不缓存任何数据。适合"每个任务都要立刻被处理"的场景。
   </details>

4. **DelayQueue 如何实现"定时"？take() 是怎么阻塞到期的？**
   <details><summary>答案</summary>

   底层 PriorityBlockingQueue 按 getDelay 排序；take() 检查队首，未到期就 park 到到期时刻（Leader-Follower 模式：只有 Leader 一个线程计时）。
   </details>

5. **什么时候用 ConcurrentLinkedQueue，什么时候用 BlockingQueue？**
   <details><summary>答案</summary>

   需要阻塞（put/take）→ BlockingQueue；不需要阻塞（offer/poll）且要无锁高吞吐 → ConcurrentLinkedQueue。线程池任务队列用 BlockingQueue，Netty 的异步队列用 ConcurrentLinkedQueue。
   </details>
