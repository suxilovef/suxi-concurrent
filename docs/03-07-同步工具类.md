## 1. 总览：三个同步工具

```
┌──────────────┬────────────────────────┬─────────────────────────┐
│ 工具          │ 解决的问题              │ 类比                    │
├──────────────┼────────────────────────┼─────────────────────────┤
│ CountDownLatch│ 等待 N 个任务全部完成    │ 多人拼车：等所有人都上车   │
│ CyclicBarrier │ N 个线程同时到达再一起走  │ 赛跑：等所有人到起跑线    │
│ Semaphore     │ 同时最多 N 个线程进入     │ 停车场：最多停 N 辆车     │
└──────────────┴────────────────────────┴─────────────────────────┘

关键区别（面试必考）：
  CountDownLatch：主线程等子线程（"等"的是一方）
  CyclicBarrier：所有线程互相等（"等"的是彼此）
  Semaphore：限制并发数（不是等待，是限量）
```

## 2. CountDownLatch（倒计时门闩）

### 2.1 是什么

> **一个线程（或多个）等待其他 N 个线程完成计数，计数归零后放行。**

```
CountDownLatch(3) —— 计数 3

  子线程 1 完成 → countDown() → 计数 2
  子线程 2 完成 → countDown() → 计数 1
  子线程 3 完成 → countDown() → 计数 0
                                      ↓
                        主线程 await() 放行！

主线程 await() 从调用起就一直阻塞，直到计数归零
```

### 2.2 经典用法：多任务汇总

```java
// 场景：并发查 3 个数据源，全部完成后汇总
public class DataAggregationDemo {
    public static void main(String[] args) throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(3);  // 等 3 个任务
        Map<String, Object> results = new ConcurrentHashMap<>();

        // 并发执行 3 个查询
        for (int i = 1; i <= 3; i++) {
            final int id = i;
            new Thread(() -> {
                try {
                    Thread.sleep(200 * id);   // 模拟查询耗时
                    results.put("source" + id, "data-" + id);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();        // 完成 → 计数 -1（必须 finally！）
                }
            }, "query-" + id).start();
        }

        latch.await();                        // 主线程等所有查询完成
        System.out.println("所有查询完成，汇总结果: " + results);
    }
}
```

### 2.3 await 的两种形态

```java
// 无限等待
latch.await();

// 限时等待：最多等 3 秒，超时继续往下走
boolean done = latch.await(3, TimeUnit.SECONDS);
if (!done) {
    // 超时降级：部分数据缺失也能继续
}
```

### 2.4 源码原理（基于 AQS 共享模式）

```java
public class CountDownLatch {
    // 内部 Sync 继承 AQS
    private static final class Sync extends AbstractQueuedSynchronizer {
        // state = 初始计数
        Sync(int count) { setState(count); }

        // countDown → tryReleaseShared：state -1，归零返回 true（唤醒所有等待者）
        protected int tryAcquireShared(int acquires) {
            return (getState() == 0) ? 1 : -1;   // 计数不为 0 → 获取失败
        }

        protected boolean tryReleaseShared(int releases) {
            for (;;) {
                int c = getState();
                if (c == 0) return false;        // 已经归零
                int nextc = c - 1;
                if (compareAndSetState(c, nextc))
                    return nextc == 0;           // 归零 → 唤醒所有 await 的线程
            }
        }
    }

    public void countDown() { sync.releaseShared(1); }
    public void await() throws InterruptedException {
        sync.acquireSharedInterruptibly(1);
    }
}
```

```
原理一句话：
  countDown() = releaseShared（state -1）
  await() = acquireShared（state != 0 就阻塞）
  state 归零 → 所有等待者被唤醒（setHeadAndPropagate 传播机制）
```

### 2.5 注意：不可复用

```java
// ⚠️ CountDownLatch 的计数只能减不能加
CountDownLatch latch = new CountDownLatch(3);
// 3 次 countDown 后，latch 永久"放行"
// 不能重置回去再用第二次！

// 需要复用 → 用 CyclicBarrier
```

## 3. CyclicBarrier（循环屏障）

### 3.1 是什么

> **N 个线程互相等待，全部到达屏障点后，一起放行。然后自动重置，可循环使用。**

```
CyclicBarrier(3) —— 3 个线程互相等

  线程 A 到达 → await → 等待（还差 2 个）
  线程 B 到达 → await → 等待（还差 1 个）
  线程 C 到达 → await → 计数归零 → 3 个线程同时放行！
                                    ↓
                          屏障自动重置 → 下一轮可再用
```

### 3.2 经典用法：多阶段并行计算

```java
// 场景：两阶段计算，每阶段所有线程完成后才能进入下一阶段
public class CyclicBarrierDemo {
    public static void main(String[] args) {
        int threadCount = 3;
        CyclicBarrier barrier = new CyclicBarrier(threadCount, () -> {
            // 全部到达后执行（可选：屏障动作）
            System.out.println("=== 本阶段全部完成，进入下一阶段 ===");
        });

        for (int i = 1; i <= threadCount; i++) {
            final int id = i;
            new Thread(() -> {
                try {
                    // 阶段 1
                    Thread.sleep(100 * id);
                    System.out.println("线程" + id + " 完成阶段 1");
                    barrier.await();    // 等所有人完成阶段 1

                    // 阶段 2（所有人到达后才执行）
                    Thread.sleep(50 * id);
                    System.out.println("线程" + id + " 完成阶段 2");
                    barrier.await();    // 等所有人完成阶段 2

                    System.out.println("线程" + id + " 全部完成 ✅");
                } catch (InterruptedException | BrokenBarrierException e) {
                    Thread.currentThread().interrupt();
                }
            }, "T" + id).start();
        }
    }
}
```

### 3.3 源码原理（ReentrantLock + Condition）

```java
public class CyclicBarrier {
    // 核心：ReentrantLock + Condition
    private final ReentrantLock lock = new ReentrantLock();
    private final Condition trip = lock.newCondition();
    private final int parties;          // 总线程数
    private int count;                  // 剩余等待数
    private Generation generation;      // 代（每轮屏障 = 一代）

    public int await() throws InterruptedException, BrokenBarrierException {
        lock.lock();
        try {
            ...
            int index = --count;         // 剩余等待数 -1
            if (index == 0) {            // 最后一个到达！
                nextGeneration();        // 重置代 + 唤醒所有人
                return 0;
            }
            // 不是最后一个 → 等待
            for (;;) {
                if (generation != g) return index;  // 换代了（被唤醒）
                trip.await();                       // 阻塞等待
                ...
            }
        } finally {
            lock.unlock();
        }
    }
}
```

### 3.4 Generation（代）机制

```
为什么需要 Generation？

CyclicBarrier 可复用 → 需要区分"这一轮"和"下一轮"
每一轮 = 一个 Generation

Generation 破坏（Broken）：
  如果某个线程 await 时被中断/超时 → 屏障"打破"
  → 其他等待的线程抛 BrokenBarrierException
  → 整轮作废，不能继续

三种状态：
  正常轮：所有线程到达 → nextGeneration() → 新一轮
  破坏轮：有线程超时/中断 → 屏障 broken → 抛 BrokenBarrierException
  恢复：只能通过 reset() 显式重置
```

### 3.5 CountDownLatch vs CyclicBarrier（⭐ 必考）

| 维度 | CountDownLatch | CyclicBarrier |
|---|---|---|
| 等待方式 | 主线程等子线程（单向） | 所有线程互相等（双向） |
| 可复用 | ❌ 一次性 | ✅ 循环使用 |
| 底层 | AQS 共享模式 | ReentrantLock + Condition |
| 计数方向 | 递减（countDown） | 递减（await）但自动重置 |
| 等待者 | await 的线程 | await 的线程（都是参与者） |
| 屏障动作 | 无 | ✅ 支持（Runnable barrierAction） |
| 类比 | 拼车等人 | 赛跑起跑线 |

```
一句话记忆：
  CountDownLatch：一个裁判等所有运动员跑完（裁判不跑）
  CyclicBarrier：所有运动员互相等齐才开跑（都跑，跑完还能再来一轮）
```

## 4. Semaphore（信号量）

### 4.1 是什么

> **控制同时最多 N 个线程进入临界区。获取许可（acquire）进入，释放许可（release）退出。**

```
Semaphore(3) —— 最多 3 个并发

  线程 1 acquire → 许可剩 2
  线程 2 acquire → 许可剩 1
  线程 3 acquire → 许可剩 0
  线程 4 acquire → 阻塞等待！   ← 没有许可了
  ...
  线程 1 release → 许可剩 1 → 唤醒等待的线程 4
```

### 4.2 经典用法：限流 / 连接池

```java
// 场景 1：接口限流（最多同时 5 个请求处理）
public class RateLimitDemo {
    private final Semaphore limiter = new Semaphore(5);

    public void handleRequest() {
        if (!limiter.tryAcquire()) {          // 拿不到许可 → 快速失败
            throw new RuntimeException("系统繁忙，请稍后重试");
        }
        try {
            process();
        } finally {
            limiter.release();                // 必须释放！
        }
    }
}

// 场景 2：数据库连接池
public class ConnectionPool {
    private final Semaphore semaphore = new Semaphore(10);  // 最多 10 个连接
    private final List<Connection> connections = ...;

    public Connection getConnection() throws InterruptedException {
        semaphore.acquire();                   // 没有空闲连接则阻塞
        try {
            return connections.remove(0);      // 取出连接
        } catch (Exception e) {
            semaphore.release();               // 获取失败也要还许可
            throw e;
        }
    }

    public void returnConnection(Connection conn) {
        connections.add(conn);
        semaphore.release();                   // 归还许可
    }
}
```

### 4.3 公平性

```java
new Semaphore(3);                 // 非公平（默认）：acquire 直接抢
new Semaphore(3, true);           // 公平：先来先得（避免饥饿）

// 同 ReentrantLock 的道理：非公平吞吐高，公平防饥饿
```

### 4.4 与锁的区别（⭐ 常见混淆）

```
Semaphore 不是锁！

锁（Lock）：获取锁的线程 = 持有者，释放只能由持有者
信号量（Semaphore）：acquire/release 不绑定线程！

  ✅ 线程 A acquire，线程 B 也可以 release（计数 +1）
  ❌ 这可能导致"幽灵许可"—— 没 acquire 的人也能 release
  → 使用规范：acquire 和 release 必须在同一个 try-finally 内配对

Semaphore(1) 也不等于锁：
  锁有持有者概念（可重入、可中断）
  Semaphore(1) 只是"最多 1 个"，没有持有者概念
```

## 5. Exchanger（交换器，○ 了解）

### 5.1 是什么

> **两个线程交换数据：双方都到达交换点后，互换对方的数据。**

```
线程 A 持有 dataA ──┐
                    ├──→ 交换点（双方都到达）──→ A 得到 dataB，B 得到 dataA
线程 B 持有 dataB ──┘

exchanger.exchange(myData) → 阻塞直到另一个线程也调用 exchange → 返回对方的数据
```

### 5.2 典型应用

```java
// 场景：两个线程各生产一批数据，交换后各自处理对方的数据
Exchanger<List<Integer>> exchanger = new Exchanger<>();

// 线程 1
List<Integer> myList = produce();              // 生产数据
List<Integer> otherList = exchanger.exchange(myList);  // 交换
process(otherList);                            // 处理对方的数据

// 线程 2 同样操作
// 效果：双方各得对方的数据，且交换是"一对一配对"的
```

> ○ Exchanger 源码是 JUC 中最复杂的（Slot + CAS + park/unpark），日常使用极少，了解用途即可。

## 6. Phaser（阶段器，○ 了解）

### 6.1 是什么

> **CyclicBarrier 的增强版：支持动态注册/注销参与者，可以分多个阶段。**

```
CyclicBarrier 的局限：
  参与者数量固定（构造时定死）

Phaser 的优势：
  阶段可多轮（每轮 = 一个 phase）
  参与者可动态增减（register / arriveAndDeregister）

对比：
  CountDownLatch   = 一次性门闩
  CyclicBarrier    = 循环屏障（人数固定）
  Phaser           = 循环屏障（人数可变 + 多阶段）
```

### 6.2 基本使用

```java
// 使用示例：3 个参与者，两阶段任务
Phaser phaser = new Phaser(3);   // 3 个参与者

// 每个线程
for (int phase = 1; phase <= 2; phase++) {
    doWork(phase);                  // 执行阶段工作
    phaser.arriveAndAwaitAdvance(); // 到达并等待所有人
}
```

### 6.3 动态注册

```java
Phaser phaser = new Phaser(2);     // 初始 2 个
phaser.register();                 // 动态 +1（现在 3 个）
phaser.arriveAndDeregister();      // 到达并 -1（退出参与）

// 场景：计算任务数量动态变化的并行计算
```

## 7. 生产注意事项 & 常见坑点

### 🕳️ 坑 1：countDown 忘记放 finally —— 永远等不到

```java
// ❌ 子线程抛异常 → countDown 没执行 → 主线程永远 await
new Thread(() -> {
    doWork();             // 这里抛异常！
    latch.countDown();    // 永远执行不到
}).start();
latch.await();            // 永远阻塞 → 死锁

// ✅ countDown 必须放 finally
new Thread(() -> {
    try {
        doWork();
    } finally {
        latch.countDown();   // 无论成功失败都计数
    }
}).start();
```

### 🕳️ 坑 2：await 无限等待导致"假死"

```java
// ❌ 主线程 await() 无限等待，如果子线程永远不完成 → 应用卡死
latch.await();

// ✅ 生产规范：尽量用限时等待
if (!latch.await(5, TimeUnit.SECONDS)) {
    log.warn("等待超时，部分任务未完成，降级处理");
}
```

### 🕳️ 坑 3：CyclicBarrier 的 BrokenBarrierException

```java
// ⚠️ 一个线程超时/中断 → 屏障打破 → 其他所有线程抛 BrokenBarrierException
// 处理：捕获后重新组织或 reset()
try {
    barrier.await(5, TimeUnit.SECONDS);
} catch (BrokenBarrierException e) {
    // 屏障已破坏 → 决定是重试还是放弃
    barrier.reset();   // 显式重置
}
```

### 🕳️ 坑 4：Semaphore 的 release 泄漏

```java
// ❌ 忘记 release → 许可越来越少 → 最后所有线程阻塞
semaphore.acquire();
doWork();
// 忘写 release！

// ✅ 必须 try-finally
semaphore.acquire();
try {
    doWork();
} finally {
    semaphore.release();
}
```

### 🕳️ 坑 5：Semaphore 的许可可以被"乱释放"

```java
// ⚠️ Semaphore 不绑定线程：没 acquire 的线程也能 release
// 线程 B 直接调 release() → 许可凭空 +1 → 超发许可
// → 规范：acquire 和 release 严格配对（同一线程、同一 try-finally）
```

### 🕳️ 坑 6：CountDownLatch 用完后想复用

```java
// ❌ 不能复用！用过的 latch 计数已归零
latch.await();   // 直接放行（已经归零）

// ✅ 复用场景用 CyclicBarrier 或 Phaser
```

## 8. 面试高频考点

1. **CountDownLatch 和 CyclicBarrier 的区别？**
   → 单向等待 vs 互相等待；一次性 vs 循环使用；AQS vs Lock+Condition；CyclicBarrier 支持屏障动作。

2. **Semaphore 和锁的区别？**
   → 锁有持有者概念（可重入、必须持有者释放）；Semaphore 只计数不绑定线程。

3. **CountDownLatch 的原理？**
   → AQS 共享模式：countDown = releaseShared（state-1），await = acquireShared（state≠0 阻塞），归零唤醒所有。

4. **CyclicBarrier 的 Generation 是什么？**
   → 每轮屏障 = 一代。一代被破坏（超时/中断）→ 所有等待者抛 BrokenBarrierException。

5. **Semaphore 怎么限流？tryAcquire 和 acquire 的区别？**
   → acquire 阻塞等待许可；tryAcquire 立即返回（拿不到 false）→ 快速失败限流。

## 9. 实战练习

### 练习 1：CountDownLatch 多任务汇总（45 分钟）★必做

```java
package com.sw.yang.concurrent.juc.tools;

import org.junit.jupiter.api.Test;

import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.CountDownLatch;
import java.util.concurrent.TimeUnit;

/**
 * 练习 1：CountDownLatch 等待多个数据源查询完成再汇总
 *
 * 真实场景：接口需要并发查询用户信息、订单信息、优惠信息，全部完成后聚合返回
 */
public class CountDownLatchTest {

    @Test
    public void testAggregate() throws InterruptedException {
        final int taskCount = 3;
        CountDownLatch latch = new CountDownLatch(taskCount);
        Map<String, String> results = new ConcurrentHashMap<>();

        long start = System.currentTimeMillis();

        // 并发执行 3 个查询任务
        for (int i = 1; i <= taskCount; i++) {
            final int id = i;
            new Thread(() -> {
                try {
                    Thread.sleep(200 * id);   // 模拟不同耗时
                    results.put("source-" + id, "data-" + id);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } finally {
                    latch.countDown();        // ✅ 必须 finally！
                }
            }, "query-" + id).start();
        }

        // 限时等待（生产规范：不无限等）
        boolean allDone = latch.await(3, TimeUnit.SECONDS);
        long elapsed = System.currentTimeMillis() - start;

        System.out.println("汇总结果: " + results);
        System.out.println("总耗时: " + elapsed + "ms（串行需要 1200ms，并行约 600ms）");
        System.out.println(allDone
                ? "✅ 所有任务完成（并行使总耗时 ≈ 最慢任务）"
                : "❌ 超时，部分任务未完成");
    }

    /**
     * 对比：忘记 countDown 的效果（演示死锁风险）
     * 说明：这个测试会"卡住"，用 await(2s) 限时避免永久挂起
     */
    @Test
    public void testForgotCountDown() throws InterruptedException {
        CountDownLatch latch = new CountDownLatch(1);

        new Thread(() -> {
            try {
                Thread.sleep(100);
                // 忘了 latch.countDown()！模拟 bug
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }).start();

        boolean done = latch.await(2, TimeUnit.SECONDS);
        System.out.println(done ? "（正常完成）" : "❌ 2 秒超时——子线程忘了 countDown，await 永远等不到");
        System.out.println("（这就是为什么生产要用限时 await + countDown 放 finally）");
    }
}
```

### 练习 2：CyclicBarrier 多阶段并行（45 分钟）★必做

```java
package com.sw.yang.concurrent.juc.tools;

import org.junit.jupiter.api.Test;

import java.util.concurrent.BrokenBarrierException;
import java.util.concurrent.CyclicBarrier;

/**
 * 练习 2：CyclicBarrier 实现两阶段并行计算
 *
 * 场景：报表生成分两阶段，每阶段所有线程完成后才能进入下一阶段
 */
public class CyclicBarrierTest {

    @Test
    public void testTwoPhase() throws InterruptedException {
        final int threadCount = 3;
        CyclicBarrier barrier = new CyclicBarrier(threadCount, () ->
                System.out.println("=== 屏障触发：本阶段全部完成 ==="));

        Thread[] threads = new Thread[threadCount];
        for (int i = 0; i < threadCount; i++) {
            final int id = i + 1;
            threads[i] = new Thread(() -> {
                try {
                    // 阶段 1：并行统计
                    Thread.sleep(100 * id);
                    System.out.println("线程" + id + " 完成阶段1（统计）");
                    barrier.await();

                    // 阶段 2：并行渲染（必须等所有统计完成）
                    Thread.sleep(50 * id);
                    System.out.println("线程" + id + " 完成阶段2（渲染）");
                    barrier.await();

                    System.out.println("线程" + id + " 全部完成 ✅");
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                } catch (BrokenBarrierException e) {
                    System.out.println("线程" + id + " 屏障被破坏: " + e.getMessage());
                }
            }, "T" + id);
            threads[i].start();
        }

        for (Thread t : threads) t.join();
        System.out.println("✅ 两阶段并行完成（屏障自动重置了 2 次）");
    }

    /**
     * 演示：CountDownLatch 无法复用，CyclicBarrier 可以
     */
    @Test
    public void testReusable() throws InterruptedException, BrokenBarrierException {
        CyclicBarrier barrier = new CyclicBarrier(2);

        // 第一轮
        Thread t1 = new Thread(() -> {
            try { barrier.await(); } catch (Exception e) { Thread.currentThread().interrupt(); }
            System.out.println("第一轮：两个线程都到了");
        });
        t1.start();
        barrier.await();
        t1.join();

        // 第二轮（无需重建对象！）
        Thread t2 = new Thread(() -> {
            try { barrier.await(); } catch (Exception e) { Thread.currentThread().interrupt(); }
            System.out.println("第二轮：CyclicBarrier 复用成功");
        });
        t2.start();
        barrier.await();
        t2.join();

        System.out.println("✅ CyclicBarrier 可循环使用（CountDownLatch 做不到）");
    }
}
```

### 练习 3：Semaphore 限流（30 分钟）

```java
package com.sw.yang.concurrent.juc.tools;

import org.junit.jupiter.api.Test;

import java.util.concurrent.Semaphore;
import java.util.concurrent.atomic.AtomicInteger;

/**
 * 练习 3：Semaphore 实现接口限流（最多同时 3 个请求）
 */
public class SemaphoreTest {

    private final Semaphore semaphore = new Semaphore(3);
    private final AtomicInteger concurrent = new AtomicInteger(0);
    private final AtomicInteger maxConcurrent = new AtomicInteger(0);
    private final AtomicInteger rejected = new AtomicInteger(0);

    // 模拟接口：最多 3 个并发
    private void handleRequest(int id) throws InterruptedException {
        // 用 tryAcquire 快速失败限流
        if (!semaphore.tryAcquire()) {
            rejected.incrementAndGet();
            System.out.println("请求 " + id + " 被拒绝（系统繁忙）");
            return;
        }
        try {
            int cur = concurrent.incrementAndGet();
            maxConcurrent.accumulateAndGet(cur, Math::max);
            Thread.sleep(100); // 模拟业务
            concurrent.decrementAndGet();
            System.out.println("请求 " + id + " 处理完成");
        } finally {
            semaphore.release();   // ✅ 必须释放
        }
    }

    @Test
    public void testRateLimit() throws InterruptedException {
        // 10 个并发请求
        Thread[] threads = new Thread[10];
        for (int i = 0; i < 10; i++) {
            final int id = i;
            threads[i] = new Thread(() -> {
                try {
                    handleRequest(id);
                } catch (InterruptedException e) {
                    Thread.currentThread().interrupt();
                }
            }, "req-" + id);
            threads[i].start();
        }
        for (Thread t : threads) t.join();

        System.out.println("最大并发: " + maxConcurrent.get());
        System.out.println("被拒绝数: " + rejected.get());
        System.out.println(maxConcurrent.get() <= 3
                ? "✅ 并发从未超过 3（限流生效）"
                : "❌ 超过 3 个并发！");
    }
}
```

## 10. 自测题

1. **CountDownLatch 和 CyclicBarrier 的区别（至少 3 点）？**
   <details><summary>答案</summary>

   ① 等待关系：单向（主等子）vs 互相等；
   ② 复用：一次性 vs 循环；
   ③ 底层：AQS 共享模式 vs ReentrantLock+Condition；
   ④ 屏障动作：无 vs 支持 Runnable。
   </details>

2. **CountDownLatch 的 countDown 为什么必须放 finally？**
   <details><summary>答案</summary>

   子线程如果抛异常提前结束，不放 finally 的 countDown 永远执行不到 → 主线程 await 永久阻塞 → 死锁。
   </details>

3. **CyclicBarrier 的 Generation 破坏是怎么回事？**
   <details><summary>答案</summary>

   某线程 await 时超时或中断 → 当前 Generation 标记为 broken → 其他所有等待线程抛 BrokenBarrierException → 整轮作废，需 reset() 或重建。
   </details>

4. **Semaphore 和锁的根本区别？**
   <details><summary>答案</summary>

   锁有持有者（必须持有者释放、可重入、可中断）；Semaphore 只是计数器，不绑定线程，release 可以由任何线程调用。
   </details>

5. **Semaphore(1) 能替代锁吗？**
   <details><summary>答案</summary>

   不能完全替代。Semaphore(1) 只是"最多 1 个许可"，没有持有者概念（其他线程也能 release）、不可重入、不能处理中断的持有者语义。互斥语义场景用 ReentrantLock 更安全。
   </details>
